## Live-feed ordering (first implementation slice)

| State/order | Owner and result |
| --- | --- |
| Subscribe pending, response followed immediately by first event | Transport installs server ID synchronously while decoding response, before resuming caller; first replacement stays in bounded stream |
| Cancel before subscribe response | Retain pending registration identity until response/failure; unsubscribe acknowledged server ID without delivering |
| Rapid replacement requests B then C during A admission | Latest slot version owns admission; wake obsolete waiters so B cannot reopen after C or accumulate behind A |
| Replacement while old registration is pending | Wait for its bounded registration settlement and unsubscribe acknowledgement before admitting the replacement; cancellation tombstones do not cause a permanent replacement refusal |
| Cancel after registration | Retire that local stream and track unsubscribe through its acknowledgement, including asynchronous termination callbacks; replacement waits for cleanup on the same connection generation, late events ignored |
| Full replacement updates burst faster than UI consumes | Keep newest replacement per subscription, bounded to one frame |
| Foreign conversation or malformed cursor | Finish only that stream with typed invalid-frame error; request cleanup |
| Subscription terminal frame | Finish with typed reason; retry only lag/source closure under reconnect policy, never refusal/oversize |
| Socket failure/replacement | Fail pending requests and streams; old connection events cannot mutate new registration |

Review: first-frame installation precedes waiter resumption; stream correlation uses connection-local subscription identity, not conversation title; list/view frames are complete replacement publications, so newest-only buffering is valid. Domain/application own values and ports; the transport adapter owns wire correlation and cleanup. Durable replay and native paired authority stay explicit later gates.

## Durable display and connection recovery slice

This slice keeps derived replacement views for fast/offline display; it does not declare retained checkpoints. An injected application snapshot session owns one current identity lease and a single coalescing writer. The private filesystem adapter bounds decoded/encoded bytes and cached view count, validates view-key correlation, uses atomic replacement and excludes its directory from backup. Scope includes endpoint, device instance and credential fingerprint. Changing credentials or endpoints cannot expose the old cache. Inbox replacements select unarchived chats: absence, even from a complete list, does not prove deletion. Explicit confirmed deletion evicts its transcript and fences late views/lists. Retained tombstones remain shared-core owned.

Manual connect loads the matching snapshot before dialing. A transport failure keeps that display and starts one cancelable recovery loop with bounded exponential delay; explicit protocol/auth refusals stop retries. Backgrounding retires feeds/socket, flushes snapshots and fences callbacks. Foregrounding reconnects and starts fresh inbox/visible-thread feeds. UI task identity includes the connection revision, so reconnecting with the same chat ID still replaces its feed. A successful adapter dial returns an opaque local socket lease atomically with authentication. Post-authentication failure/cancellation retires only that lease; a stale caller cannot close its replacement. Background retirement is ordered before a foreground dial, which checks ownership before and after cache hydration. Manual attempts block overlapping foreground recovery. Reopening a snapshot scope settles its outgoing writer before loading disk. Commands are not replayed by this loop; durable command identity/receipt recovery is a subsequent part of gate 3.

Verification: filesystem recreation and scope isolation; corruption, oversize and mismatched view identity refusal; snapshot writer serialization under delayed saves; archived absence versus confirmed deletion and late resurrection; offline cold display; disconnect/reconnect restoring an open chat; background/foreground; old connection completions fenced; typed refusal does not retry. Review the plan and implementation independently, then run the app suite, scripted faults and simulator startup before publishing.

Review and evidence: Astra medium passed the final cache/recovery implementation after fixes for pending-save hydration and obsolete recovery preparing a newer cache scope. Both fixes were deliberately reverted separately and the regression tests failed at runtime; restored source passes 87 tests and the iOS build. Seven scripted production-adapter faults pass. The installed simulator survives an isolated gateway shutdown, restores the inbox, transcript and same-device photo on a cold offline relaunch, then reconnects automatically after gateway restart. Post-restart message and image checks pass; details are in RESULTS.md. Gate 3 remains open for durable command identity/receipt recovery, and gate 4 remains open for the actual shared retained core.

Interrupted-command follow-up: retiring a connected generation releases transient Send/Create UI locks without replaying either command. Stale command completions cannot clear replacement operation state. Agent-cache publication checks ownership before capturing its scope and after recording, and readiness publication has no suspension. Held-send/create and directory-scope tests pass; deliberate reverts fail; Astra medium passed the implementation.

## Durable command foundation

The gateway already owns principal-bound creation/submission receipts. The phone now has immutable prepared create/submit values with stable request, conversation and execution identities and ordered image references. The application journal saves the full intent before dispatch, keeps unknown/not-yet-recorded/attempted progress unresolved, and persists explicit acknowledged resolution before removing it. Cancellation, lost responses and failed resolution saves preserve the original intent. Neither reconnect nor receipt lookup replays it. A new user intent must have a new identity; payload equality is not an intent identity.

Command storage is stricter than derived display storage: at most 32 unresolved intents and 1 MiB per identity, no eviction on corruption/quota, and no dispatch after failed persistence. A stable private regular-file OS lock covers validation, compare-and-swap, atomic replacement and synchronization. Separately constructed stores reject stale insertions and resolutions, including missing versus existing-empty documents. The application actor serializes its owned saves and publishes memory before waking subsequent mutations. Scope replacement settles outgoing saves and fences old callers. Shared bounded/private file I/O serves both snapshots and commands without sharing their failure policies.

The typed socket port checks its current connection lease and authenticated endpoint/instance/credential scope immediately before registration, and validates create/send acknowledgments and kind-specific receipts against their returned identities. Its exact-ID retry primitives reuse the frozen payload. Scripted peers accept then close before acknowledgment; a recreated disk journal recovers each receipt and an exact retry produces one effect. A real gateway experiment repeats create and submit IDs, recreates storage, resolves the saved receipt and verifies one turn. Astra medium passed the foundation; removing CAS or the authority-scope check fails runtime regressions.

This is a foundation approval, not completion of gate 3: existing repository create/send paths are still legacy. Next wire composition and composer/create identity ownership to the journal; show pending delivery, restore pending intents on launch, and clear only the original draft after confirmation. Never infer a retry from equal text or silently issue a new ID after uncertainty. Persist uncertain deletions separately and resolve only with exact read/not-found or retained tombstone proof (the receipt operation enum has no delete). The shared retained mobile-core integration remains gate 4.

## Product command integration

The next reviewed slice wires live composition, repository create/send and composer identity ownership to the journal. Pending intents hydrate before readiness; journal failures keep reads available but fail writes closed. Check reads a receipt without dispatch; explicit Retry looks up then dispatches the same frozen intent only if still unresolved. Atomic admission blocks a different pending creation or a different submission in the same chat, including concurrent attempts after uploads. Captured draft scope/revision and request identity fence late confirmations; editing, retyping identical text, changing attachments/replies or replacing the account cannot lose a newer draft. Frozen reply identity is restored when receipt recovery confirms delivery. Known network acceptance survives failed local resolution, while the pending record remains.

Every dispatch entry point persists a bounded attempt claim before handoff. Historical documents missing attempt state are conservatively uncertain. Audited, operation-specific first-attempt model/agent/photo refusals can release the exact reservation without marking acceptance or clearing the draft; a concurrent/later attempt or CAS mismatch prevents that release. Transport, generic server, storage and audit errors never prove non-delivery. An uncertain command that later receives a permanent refusal can remain pending; the existing receipt protocol lacks terminal non-delivery proof for that case. This limitation stays explicit rather than discarding an identity that could already have taken effect.

Astra medium passed the final implementation after fixes for permanent first-attempt refusals and a legacy execution bypass. The 119-test suite includes draft mutation/late completion, gated Check/Retry through connection/account replacement, frozen reply restoration, failed hydration/resolution, serialized admission, attempt persistence/cancellation/migration and mixed execution/CAS. Removing attempt tracking and draft revision ownership separately fails runtime regressions. Product wire faults recreate the app owners and disk journal, preserve one effect after lost ACK, distinguish Check from explicit Retry, preserve uncertainty after a later refusal, and fail commands closed on corrupt binding. Generated live image submission and simulator startup pass. This completes create/send integration, not gate 3's uncertain deletion work or gate 4's retained core.
